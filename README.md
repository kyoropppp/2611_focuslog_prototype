# FocusLog — 研究・哲学・LLM の時間割と実績を記録するプロトタイプ

モデル時間割と実績を、**「場所・移動」と「活動」に分けた4段**で同じ時間軸に並べて比較する個人用アプリです（v0.4）。

「通学中に研究した」「移動中に哲学書を読んだ」のように、**場所と活動が重なる時間**をそのまま記録・比較できます。

画面イメージは `docs/preview_desktop.png`（PC）と `docs/preview_mobile.png`（スマートフォン）で確認できます。

## 動作環境

- **Python 3.10以上**
- デスクトップアプリとして使う場合：`pywebview`（Windows 10/11 は標準の WebView2 を使用）
- ブラウザで使う場合：追加ライブラリ不要。Windows / macOS / Linux のモダンブラウザ

## 起動方法

### デスクトップアプリ（PC専用・推奨）

- `start_app_windows.bat` をダブルクリック（初回は pywebview を自動インストール）
- または `python app.py`

ブラウザではなく専用ウィンドウで開きます。内部では `127.0.0.1` の空きポートでサーバーが動きますが、外部には公開されません。ウィンドウを閉じると終了します。

**exe化：** `build_exe_windows.bat` を実行すると `dist\FocusLog.exe` が作られます。exe版のデータは exe と同じ場所の `data\focuslog.db` に保存されるため、使い始める前に exe を `dist` 以外の場所へ移してください。

### ブラウザ版（スマホからも使う場合）

1. `start_windows.bat` をダブルクリック（または `py -3 server.py --host 0.0.0.0`）
2. PCのブラウザで **http://127.0.0.1:8765** を開く
3. スマホからは同じWi-Fiで `http://PCのローカルIP:8765` を開く（IPは PowerShell の `ipconfig` で確認）

Windowsファイアウォールで、プライベートネットワークへの Python の着信を許可する必要がある場合があります。終了は起動したウィンドウで **Ctrl+C**。macOS / Linux は `python3 server.py --host 0.0.0.0`。

## 画面の構成：4段タイムライン

| グループ | 段 | 内容 |
|---|---|---|
| モデル | 場所・移動 | 自宅 / 研究室 / 移動中 / その他 の予定 |
| モデル | 活動 | 研究・哲学・LLM、固定予定（バイト・ゼミ等）、休憩、マージン |
| 実績 | 場所・移動 | 実際にいた場所・移動した時間 |
| 実績 | 活動 | 実際に行った研究・哲学・LLM（テーマ・作業内容・メモ） |

- 4段は共通の時間軸で、まとめて横スクロールします。左端の「モデル／実績」「場所／活動」のラベルは固定表示です。
- タイムライン右上の **「場所・移動」** チェックを外すと、場所の2段を隠して従来に近い2段（活動の予定・実績）で比較できます（表示状態は端末ごとに記憶）。
- **場所と活動は独立しています。** 同じ時間帯に重なっていても正常で、警告もしません。

### 操作

- **モデルのバーを押す** → 「場所・移動の実績を追加」「活動の実績を追加」「モデル予定を編集」から選択。実績を追加する場合は、予定の開始・終了時刻が初期値として入ります（保存前に自由に変更可）。
  - 移動の予定から活動実績を追加しても、研究・哲学・LLMを自由に選べます。
  - 実績は**保存したときだけ**記録されます。予定があるだけで「移動した」「研究した」ことにはなりません。
- **空白を押す** → その段に、押した時刻（15分単位）から1時間の新規登録。予定がない時間帯にも、場所・活動の実績を追加できます。
- **実績のバーを押す** → 編集・削除。
- モデル予定は従来どおり **この日だけ変更 / 毎週この曜日を変更** に対応。

### モデル予定の編集（編集モード）

タイムライン下の **「モデル予定を編集」** を押すと編集モードになります。モデルの段が強調され、実績やほかの部分は暗くなります。

- **長さを変える**：バーの左右の端をドラッグ（15分単位）。動くのはその予定だけで、隣と重なった場合は段を分けて表示します。
- **細かく設定**：バーを押すと、時刻・種類・名前・研究目標を入力できます（削除もここから）。
- **追加**：空白を押す、または「予定を追加」。
- **元に戻す**：直前の操作を取り消します。
- 変更はすべて**下書き**です。**「変更を保存（n件）」** を押すと、保存先を選びます。
  - **この日だけ**：その日だけ変更（他の日には影響しません）
  - **毎週の◯曜日**：今後のすべての同じ曜日に反映（その日がパターン適用中・変更済みの場合は選べません。先に解除してください）
- 「終了」や日付の移動、更新ボタンを押すと、保存していない変更は確認のうえ破棄されます。
- 研究の予定は長さに合わせて研究目標も変わります。移動の予定を研究目標より短くすると、目標は予定の長さまで自動で減ります。

### 更新ボタン

アプリのウィンドウでは Ctrl+F5 が効かないため、右上の 🔄 ボタンで画面を最新の状態に読み込み直せます。

### この日の予定の切り替え（輪読なし・ゼミなし など）

曜日によっては、予定が変わる日のための**別パターン**を用意しています。タイムライン下のボタン（「モデル予定を編集」の左）で切り替えます。

| 曜日 | パターン | 内容 |
|---|---|---|
| 火 | 輪読なし | 10:00〜12:00 の LLM輪読を研究に変更 |
| 金 | ゼミなし | 通学・ゼミなし。土曜と同じく午前〜昼過ぎに研究（目標6h）、午後は哲学・LLM |

ボタンはその日の状態に応じて1つだけ表示されます。

| その日の状態 | ボタン |
|---|---|
| いつもの予定（パターンのある曜日） | 「この日を『ゼミなし』にする」 |
| パターン適用中 | 「この日の『ゼミなし』を解除する」 → いつもの予定に戻る |
| 「この日だけ」予定を変更した日 | 「この日だけの変更を解除する」 → いつもの予定に戻る |

- 適用はその日だけで、他の週には影響しません。
- パターン適用後に「この日だけ」予定を修正しても、パターン名は残ります（解除ボタンも同じ）。
- 2026/11/17 は「輪読なし」を適用済みです。

### 移動中の研究目標

火曜・金曜の通学（08:00〜10:00）には「研究目標90分」が設定されています。これは**2時間の移動の中で合計90分研究したい**という目標で、08:00〜09:30 に研究する予定ではありません。

- 活動の段には、移動の時間帯全体に **点線の枠「研究目標 90分（時刻未指定）」** として表示します。確定した研究予定のバーは作りません。
- 研究の予定時間（日・週の目標）には従来どおり90分を含めます。
- 実際の研究時間は **活動の実績だけ** から集計します。

例：場所の実績「08:00〜10:00 移動中」＋活動の実績「08:20〜09:20 研究」「09:25〜09:55 哲学」 → 移動120分・研究60分・哲学30分（移動時間は活動時間に加算しない）。

## その他の機能

- 日付移動（前日・翌日・カレンダー）、7:00〜23:00 の時間軸（設定で変更可）
- 活動実績の手入力：日付、開始・終了、カテゴリ（研究・修論 / 哲学 / LLM）、テーマ、作業内容、メモ
- テーマの入力補助・新規登録・名前変更・アーカイブ
- 活動実績どうしの時間重複は警告のみ（保存可、集計では合算）
- 日ごとの実績と研究の予定時間、週ごとの集計グラフ（場所・移動の合計も参考表示）
- エクスポート：活動実績CSV、場所・移動CSV、全データJSON
- SQLiteによる永続保存（ブラウザ版では、同じサーバーに接続したスマホと同期）

## 初期モデル時間割

- 月・水：7:00〜12:00 研究（9:30〜10:00 休憩）、13:00〜18:00 オンラインバイト、18:00以降マージン。月曜は 21:00〜23:00 講師MTG。
- 火：8:00〜10:00 通学（研究目標90分）、10:00〜12:00 LLM輪読、12:00〜14:00 昼食会。輪読がない日は「輪読なし」パターン（**2026/11/17** は適用済み）。
- 木：7:00〜11:00 研究、15:00〜23:00 バイト。
- 金：7:00〜8:00 研究、8:00〜10:00 通学（研究目標90分）、10:00〜13:30 研究、17:00〜20:00 ゼミ（準備枠なし）。ゼミがない日は「ゼミなし」パターン（土曜型）。
- 土日：午前〜昼過ぎに研究、午後は哲学・LLMを任意で実施。

自宅・研究室の予定は**登録していません**。場所が不明な時間を自宅や研究室と推定して自動登録することはありません。必要に応じて「場所・移動」段に追加してください。

## データの保存と移行

- 保存先：`data/focuslog.db`（環境変数 `FOCUSLOG_DATA_DIR` で変更可）。実データなので適宜バックアップしてください。
- **v0.1 → v0.2 の移行は起動時に自動で行います。**
  1. 変更前に `data/backups/focuslog_<日時>_before_v2.db` へバックアップを作成
  2. 場所・移動の実績用テーブル `place_logs` を追加
  3. `preferences.schema_version` を記録（再起動しても移行・バックアップは繰り返されません）
- **v0.2 → v0.3** も起動時に自動移行します（バックアップ `..._before_v3.db` を作成）。
  - 曜日ごとの別パターン用テーブル `day_patterns` を追加し、火曜「輪読なし」・金曜「ゼミなし」を登録
  - `day_overrides` に `pattern_name` 列を追加し、既存の 11/17 を「輪読なし」の適用日として扱う
- 既存データの扱い：
  - 活動実績（`logs`）・テーマ・毎週のモデル・日付ごとの例外（11/17含む）はそのまま引き継ぎます。
  - 予定の段は種類から決まります。`travel` → モデルの場所・移動（研究目標 `goal_minutes` も維持）、`research / philosophy / llm / fixed / break / margin` → モデルの活動。既存の予定データは書き換えません。
  - 場所の実績は推測で作りません（移行直後は空）。
- JSONインポート機能はありません。別のPCで使う場合はDBファイルをコピーしてください。

### データ構造

| テーブル | 内容 |
|---|---|
| `weekly_plans` | 曜日ごとのモデル予定（`kind` で活動／場所・移動の段が決まる） |
| `day_overrides` | 「この日だけ」変更した日のモデル（JSONスナップショット）と、適用したパターン名 `pattern_name` |
| `day_patterns` | 曜日ごとの別パターン（例：火曜「輪読なし」、金曜「ゼミなし」） |
| `logs` | 活動の実績 |
| `place_logs` | 場所・移動の実績（日付・開始・終了・種類 `home/lab/travel/other`・メモ） |
| `themes` | テーマ |
| `preferences` | 表示範囲、`schema_version` |

### API

| メソッド・パス | 内容 |
|---|---|
| `GET /api/day?date=` | その日のモデル（各予定に `lane: activity/place`）、`logs`、`place_logs` |
| `POST /api/logs`, `PATCH/DELETE /api/logs/{id}` | 活動の実績 |
| `POST /api/place-logs`, `PATCH/DELETE /api/place-logs/{id}` | 場所・移動の実績 |
| `POST/PATCH/DELETE /api/plans` | モデル予定を1件ずつ編集（`scope: date / weekly`、`slot.kind` に場所の種類も指定可） |
| `POST /api/plans/bulk` | 編集モードの下書きをまとめて保存（`{date, scope, slots}`。毎週の場合は `weekly_id` で更新・追加・削除を判定） |
| `POST /api/day-pattern` | その日にパターンを適用（`{date, pattern_id}`）。`GET /api/day` が `patterns` と `applied_pattern` を返す |
| `DELETE /api/day-override` | その日の変更・パターンを解除して、いつもの予定（毎週のモデル）に戻す |
| `GET /api/summary?start=&end=` | 日別・期間の集計（活動時間、研究目標、場所・移動の合計 `places`） |
| `GET /api/export?format=csv / places_csv / json` | エクスポート |
| `GET/POST /api/themes`, `PATCH /api/themes/{id}`, `PATCH /api/preferences` | テーマ・設定 |

## セキュリティと制約

**認証機能はありません。インターネットに直接公開しないでください。** `--host 0.0.0.0` は同じネットワークの端末からアクセスできる状態になります。信頼できる家庭内LANでの使用を想定しています（デスクトップアプリ版は外部に公開されません）。

- PCとスマホで同時に開いた場合、日付切り替え・再読み込み時に最新データを読み込みます（自動更新なし）。
- 日付をまたぐ記録（例：23:30〜0:30）は未対応です。
- 「この日だけ変更」すると、その日のモデル全体が日付固有のスナップショットになり、以後の毎週の変更は反映されません。タイムライン下の「この日だけの変更を解除する」で戻せます。
- 表示範囲外の予定・実績はタイムラインに表示されません（一覧には表示）。
- タイマー機能はなく、実績はすべて手入力です。

## テスト

Windows では `run_tests_windows.bat` をダブルクリック。またはコマンドで：

```bash
python3 -m unittest tests.test_server -v
```

v0.1 形式のDBからの移行（バックアップ作成・データ保持・再実行で重複しないこと）、移動中の研究・哲学の記録と集計、場所・移動の実績の追加・編集・削除、研究目標が時刻つき予定にならないこと、HTTP API とエクスポートを検証します。
